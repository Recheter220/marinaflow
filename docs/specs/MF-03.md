# MF-03 — Disco de arquivos em nuvem compatível com S3

`Onda 0` · `Estimativa 3 pt` · `TODO #4` · `Habilita MF-04, MF-06`

> **Como** time, **quero** um disco de arquivos configurado e testável antes de existir upload, **para** que a história de fotos trate só de domínio e não de infraestrutura de armazenamento.

> **Desbloqueada em 02/10/2026.** `league/flysystem-aws-s3-v3` aprovada (D-01) e provedor
> decidido: **Cloudflare R2** (D-09), já habilitado. Enquanto esta história não estiver
> entregue, **nenhuma foto pode ser enviada em produção** — o filesystem da função é
> efêmero e o que for gravado fora de `/tmp` some ao fim da invocação, então a
> [MF-04](MF-04.md) e a [MF-06](MF-06.md) seguem bloqueadas por ela.

## Contexto

`FILESYSTEM_DISK=local` hoje, e as chaves AWS no `.env` estão vazias. Como `config/filesystems.php` já expõe `endpoint` e `use_path_style_endpoint`, qualquer serviço compatível com S3 serve sem alteração de código. O provedor é o Cloudflare R2, escolhido por egresso zero e presença de edge em São Paulo (D-09) — `AWS_DEFAULT_REGION` tem de ser `auto`, a única região que ele aceita. Esta história entrega apenas a fundação: disco configurado, wrapper de aplicação e URL temporária assinada — nenhuma tela.

## Requisitos funcionais

| ID | Requisito | Prioridade |
|---|---|---|
| RF-03.1 | Existe um disco `fotos` em `config/filesystems.php`, com driver S3 e visibilidade privada. | Alta |
| RF-03.2 | Em ambiente local sem credenciais, o disco cai para o driver local sem quebrar a aplicação. | Alta |
| RF-03.3 | Arquivos são servidos por URL temporária assinada com validade de 15 minutos — o bucket nunca é público. | Alta |
| RF-03.4 | `ArquivoService` encapsula gravar, gerar URL e remover, para que nenhum controller fale com o `Storage` direto. | Média |
| RF-03.5 | README documenta como obter as credenciais do bucket e como o time testa localmente. | Média |

## Contrato técnico

```
// config/filesystems.php
'fotos' => [
    'driver'                  => env('FOTOS_DISK_DRIVER', 'local'),
    'key'                     => env('AWS_ACCESS_KEY_ID'),
    'secret'                  => env('AWS_SECRET_ACCESS_KEY'),
    'region'                  => env('AWS_DEFAULT_REGION'),
    'bucket'                  => env('AWS_BUCKET'),
    'endpoint'                => env('AWS_ENDPOINT'),          // https://<projeto>.supabase.co/storage/v1/s3
    'use_path_style_endpoint' => env('AWS_USE_PATH_STYLE_ENDPOINT', true),
    'visibility'              => 'private',
    'throw'                   => true,
],

// app/Services/ArquivoService.php
public function guardar(UploadedFile $arquivo, string $pasta): string;   // devolve o path
public function urlTemporaria(string $path, int $minutos = 15): string;
public function remover(string $path): void;
```

> **Dependência aprovada em D-01:** dependência `league/flysystem-aws-s3-v3` (exigida pelo driver S3 do Laravel). Ver [D-01](README.md#decisões-técnicas).

## Critérios de aceite

**AC-03.1 — Gravação e leitura**
- **Dado** `Storage::fake('fotos')` no teste
- **Quando** `ArquivoService::guardar()` recebe um arquivo
- **Então** o arquivo existe no disco sob o caminho devolvido e `urlTemporaria()` produz uma URL assinada

**AC-03.2 — Ambiente local sem credencial**
- **Dado** um `.env` sem chaves AWS
- **Quando** a aplicação sobe
- **Então** o disco `fotos` resolve para o driver local e nenhuma exceção de configuração é lançada
