> **Como** marina, **quero** o sistema acessível pela internet com dados preservados, **para** usar no dia a dia da operação em vez de na máquina de alguém.

## Decisão de arquitetura

O TODO citava “Vercel, Render/Railway e Supabase”. A premissa de que a Vercel serviria para hospedar o frontend estava errada — o MarinaFlow é um *monólito*, o Inertia renderiza React a partir do próprio Laravel e não existe frontend separado. Mas a Vercel entra por outro caminho: o runtime comunitário `vercel-php` roda a aplicação *inteira* como função serverless.

**Decidido:** aplicação na Vercel (plano Hobby, região `gru1`/São Paulo) e PostgreSQL no Neon (`aws-sa-east-1`/São Paulo). Custo zero permanente, sem administração de servidor e sem hibernação de um minuto. Render, Railway, Northflank e Oracle Cloud foram avaliados: Railway não tem mais plano gratuito, o gratuito do Render hiberna em 15 min e não oferece worker, e Northflank e Oracle exigiriam administrar infraestrutura. Nenhum dos dois primeiros tem região na América do Sul; a Vercel e o Neon têm.

**O que o serverless custa,** e está refletido nos requisitos abaixo: não há processo longo, então `QUEUE_CONNECTION=sync`; o filesystem é somente-leitura fora de `/tmp`, o que mantém a [MF-03](MF-03.md) como pré-requisito absoluto de qualquer upload; não existe gancho de release, então migração é passo manual; e o cron do plano Hobby roda no máximo **uma vez por dia**.

## Contrato técnico

```
// vercel.json — framework:null impede a Vercel de detectar o Vite e tratar
// o projeto como site estático. As rotas de asset vêm primeiro e o catch-all
// leva todo o resto à função: NÃO usar "handle":"filesystem" — ver a armadilha abaixo.
{
    "framework": null,
    "buildCommand": "npm ci && npm run build",
    "outputDirectory": "public",
    "functions": {
        "api/index.php": { "runtime": "vercel-php@0.9.0", "maxDuration": 30, "includeFiles": "public/build/**" }
    },
    "env": {
        "APP_PACKAGES_CACHE": "/tmp/storage/framework/cache/packages.php",
        "APP_SERVICES_CACHE": "/tmp/storage/framework/cache/services.php"
    },
    "routes": [
        { "src": "/build/(.*)", "dest": "/build/$1" },
        { "src": "/favicon\\.ico", "dest": "/favicon.ico" },
        { "src": "/robots\\.txt", "dest": "/robots.txt" },
        { "src": "/(.*)", "dest": "/api/index.php" }
    ]
}

// api/index.php — o framework consulta LARAVEL_STORAGE_PATH em Application::storagePath()
$_SERVER['LARAVEL_STORAGE_PATH'] = '/tmp/storage';   // + mkdir dos subdiretórios
require __DIR__.'/../public/index.php';

// config/database.php — mesmo padrão do CloudBootstrapper do próprio framework
// banco: uma URL só. O parser do Laravel aceita o esquema `postgresql` e
// transforma a query (sslmode) em configuração — DB_HOST com a URI inteira
// faz o Laravel tentar resolvê-la como nome de host.
DB_URL=postgresql://USUARIO:endpoint%3D<id-sem-pooler>%3BSENHA@ep-...-pooler.c-2.sa-east-1.aws.neon.tech/neondb?sslmode=require

// variáveis obrigatórias em produção
APP_KEY APP_ENV=production APP_DEBUG=false APP_URL=https://...
TRUSTED_PROXIES=*  LOG_CHANNEL=stderr  LOG_LEVEL=error
DB_CONNECTION=pgsql DB_SSLMODE=require DB_PORT=5432
DB_HOST=ep-....-pooler.sa-east-1.aws.neon.tech
DB_HOST_UNPOOLED=ep-.....sa-east-1.aws.neon.tech
DB_DATABASE DB_USERNAME DB_PASSWORD
SESSION_DRIVER=database CACHE_STORE=database QUEUE_CONNECTION=sync
MAIL_MAILER=smtp MAIL_HOST MAIL_PORT MAIL_USERNAME MAIL_PASSWORD MAIL_FROM_ADDRESS
OPENWEATHER_KEY MARINA_LAT MARINA_LON
```

> **Armadilha, custou um deploy quebrado:** com `outputDirectory: "public"`, a Vercel publica `public/index.php` como arquivo estático em `/index.php`. Um `{"handle":"filesystem"}` manda checar o estático *antes* das rotas, a requisição casa com o `.php` cru — que não tem tipo de conteúdo servível — e o navegador **baixa o arquivo** em vez de abrir a aplicação; a função nunca é invocada. As rotas de asset precisam ser explícitas e o catch-all vem por último.

> **SNI do Neon, custou dois deploys.** O Neon roteia a conexão pelo nome de domínio, que o protocolo do PostgreSQL não transporta — depende da extensão SNI do TLS, e o libpq embutido no runtime serverless não a envia: `Endpoint ID is not specified`. Dos contornos que o Neon documenta, nenhum dos dois óbvios serve ao Laravel: `?options=endpoint=` cai na chave `options`, reservada para atributos do PDO, e estoura `array_diff_key(): Argument #2 must be of type array`; anexar ao nome do banco também não, porque o `PostgresConnector` emite `dbname='...'` entre aspas. O que funciona é o identificador prefixado na senha (`endpoint=<id>;<senha>`), percent-encoded dentro da URI. E o identificador vai **sem** o sufixo `-pooler`, mesmo quando o host tem.

> **Manifestos em `/tmp`.** `bootstrap/cache/` é ignorado pelo Git e o Laravel grava `packages.php` e `services.php` no boot quando eles não existem — escrita que falha em filesystem somente-leitura. `APP_PACKAGES_CACHE` e `APP_SERVICES_CACHE` os desviam para `/tmp`.

> **Não habilitar `PDO::ATTR_EMULATE_PREPARES`.** O pooler do Neon roda PgBouncer com `max_prepared_statements=1000` e suporta statements preparados no nível do protocolo, que é o que o `pdo_pgsql` usa — funciona direto. Emular sairia caro: o `prepareBindings()` do Laravel converte booleano em `int`, que interpolado vira `ativo = 1`, e o PostgreSQL recusa comparar `boolean` com `integer`.

## Critérios de aceite

**AC-13.1 — Deploy reprodutível**
- **Dado** o repositório e o README
- **Quando** alguém do time provisiona um ambiente do zero seguindo o passo a passo
- **Então** a aplicação sobe e permite login em menos de 30 minutos, sem passo não documentado

**AC-13.2 — Convite chega com URL correta**
- **Dado** um usuário convidado em produção, com `TRUSTED_PROXIES` configurado
- **Quando** o e-mail sai pelo SMTP na própria requisição
- **Então** o link usa `https` e o domínio de produção, e leva à tela de definir senha

**AC-13.3 — Os assets são encontrados**
- **Dado** o `public/build` gerado pelo `buildCommand`
- **Quando** a primeira página é renderizada pela função
- **Então** o manifest do Vite é localizado, nenhuma `ViteException` aparece no log, e `/` devolve HTML — não um download de `index.php`

**AC-13.4 — Restauração de backup**
- **Dado** um `pg_dump` do dia anterior
- **Quando** ele é restaurado em um branch do Neon
- **Então** os dados conferem e o procedimento está anotado no README

**AC-13.5 — Nada de upload antes da MF-03**
- **Dado** que o disco de nuvem está adiado e o filesystem da função é efêmero
- **Quando** o roteiro de fumaça é executado
- **Então** nenhum passo envolve envio de arquivo, e o README registra a restrição
